# 原位批注与交付质检

## 共同规则

先保留原件，再在明确命名的副本操作，例如`原名（逐处审核批注版_YYYYMMDD）`。源文件路径与输出路径不同，若目标已存在则用新版本名，不覆盖用户后续改稿。保留已有批注、修订、书签、链接、附件及数字签名信息；带数字签名或受保护文件先说明新增批注可能影响签名有效性，不绕过保护。

批注锚点要落到具体字词、数值、单元格或图表，不能全部放在段首、页首或封面。一条只解释一处一个问题；跨位置传播分别写批注。同一锚点多个独立问题各用一个ID；相同位置的同一个问题不要重复。

可用当前环境已有的Word/PDF原生工具或成熟文档库。若环境提供文档/PDF专项技能，按其要求执行；无该技能也可依下列步骤完成。选择方法前检查实际支持批注、保留图表/域/修订的能力，不能把“红色正文”冒充原生批注。

## DOCX

1. 解析文档包，定位段落、表格单元格、跨run文本及页眉页脚，保留原有样式、图片、公式、域和修订。结构化定位记录段落/表格ID及唯一原文，不用易漂移的页码作唯一锚点。
2. 使用Word原生批注API或正确OOXML批注。OOXML需同步`comments.xml`、包关系、内容类型及正文的`commentRangeStart/End`和`commentReference`；新ID不得冲突，跨run边界不得破坏字词或格式。
3. 避免全文读出后重建文档，这会丢版式。已有复杂现代批注、修订、文本框或未知内容无法保真时优先Word/兼容编辑器；先试副本并验证。
4. 文档重新打开，读取新增批注文字和锚点，核对数目及前后文；用可用的文档渲染器导出全页预览。页码以实际渲染为准，比较原件和副本正文内容及分页。

## 旧版 DOC

不能把`.doc`重命名为`.docx`。优先在能够保留格式的本地Word/兼容应用中对副本批注；需转换时保留原DOC并新建DOCX，核对分页、表格、图片、公式、页眉页脚、域和签名，明确交付格式变化。没有可靠转换/批注工具时，只能先交定位问题表并说明未完成原文批注，不能宣称批注版已生成。

## PDF

1. 提取每页文字、尺寸、旋转、CropBox及文本坐标，并渲染原图。文本层与可见内容不符时以可见原图为准；扫描页定位需视觉确认，OCR只作辅助。
2. 添加原生Highlight/Text批注，使用适当的矩形/QuadPoints，内容存为真实批注文本，不画成不可编辑页面文字；扫描图页可用紧邻目标的文本批注。保留原页面内容和已有注释。
3. 对重名词、同页重复数字、连字符/断行及旋转页，限定页与上下文、明确出现次序；零匹配/多匹配时停止该锚点自动写入，人工确认，不默认选第一个。
4. PDF坐标系可能左下原点，而文字提取坐标可能左上原点。按实际库、页框和旋转转换；不得仅用`height-y`处理所有PDF。坐标框落在页面内还不代表位置正确，需视觉验证。
5. 写入后重新打开回读ID、文本、页码、锚点和注释数量，比较源/输出页数、页面尺寸、可见内容及已有注释/链接。
6. 全部页面以相同渲染器、分辨率和关闭注释的配置比较，理想情况下像素一致；再开启批注查看目标区域是否清晰且不遮挡正文。内容流变化不必然意味视觉改变，反之亦然，两者都作为证据检查，不只对比文件大小。

## 台账与质量门槛

- `validate_findings.py`只检查台账结构，不读取PDF/Word，不验证规范真实、批注位置或计算正确。不能用其“通过”替代人工证据审查。
- 一条台账对应一条新增批注；回读后的ID、内容、位置应一致。保留原有批注单独统计，不把总批注数当成本轮新增数。
- 对照原件核查完整文本/关键XML/页面；渲染全部页并查看缩略图总览，对每个批注落点及复杂表格、公式、扫描页查看可辨认的局部。
- 若发生版式变化、公式丢失、乱码、注释错位，修复后重验；无法修复就报告限制，保留可追溯的问题表，不交称已完成的坏文件。
- 不以“未见异常”证明所有规范均满足，不承诺自动工具替代有资质专业人员复核。
