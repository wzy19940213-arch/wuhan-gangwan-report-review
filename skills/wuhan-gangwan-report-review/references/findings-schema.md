# 审核台账 v1

此台账用于将发现与原文位置、证据及处理建议对应起来。`scripts/validate_findings.py` 仅做结构质检：它不打开原报告、不联网、不执行计算表达式，也不上传、修改或证明任何报告内容。`verified: true` 是审核者的声明，不是程序已验证的事实。

本JSON结构用于已取得真实源文件的正式台账。只有粘贴摘录时，先用临时文字台账并保留未知字段，不编造文件格式或摘要来通过校验；示例中的全零摘要仅是虚构测试值，不得复制到真实报告台账。

## 根对象

必须包含以下三个字段，v1 不接受其他字段，便于发现拼写错误。

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `schema_version` | 整数 | 必须为 `1`，不能为 `true` 或 `1.0` |
| `source` | 对象 | 仅含 `name`、`sha256` |
| `findings` | 数组 | 每项是下述问题对象；允许空数组，但不代表报告合格 |

`source.name` 为非空文件名或脱敏标识。`source.sha256` 为源文件字节的 SHA-256，64 位十六进制字符串，大小写均可。校验器只检查摘要的格式，不读取源文件核对摘要。原始材料、真实台账及输出批注文件应留在授权的本地位置；公开示例必须使用纯虚构数据。

## 问题对象

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `id` | 非空字符串 | 整个台账中唯一，大小写敏感 |
| `category` | 枚举 | `technical` / `standards` / `equipment` / `calculation` / `format` / `attachments` |
| `severity` | 枚举 | `重大` / `重要` / `一般` |
| `status` | 枚举 | `confirmed`（已证实）/ `conditional`（条件成立时有问题）/ `pending`（待核） |
| `anchor` | 对象 | 一个原文位置，不能是数组；详见下节 |
| `observed` | 非空字符串 | 当前原文事实及问题，不混入未经证实的断言 |
| `basis` | 数组 | 依据对象，允许为空；不要为满足结构而虚构依据 |
| `action` | 非空字符串 | 明确修改或核实动作，不擅自改原始检测数据 |
| `calculation` | 对象，可选 | 算术复核过程；详见下节 |

其他字段不接受。一个问题涉及多处时，在各位置分别创建问题并使用独立 ID；不要将多个位置塞入 `anchor` 数组。**程序只能拒绝数组锚点，不能自动保证字符串中真的只有一个位置、一个问题，不能代替人工审查。**

复审的“已解决/未解决/部分解决/新增/现资料无法确认”状态另存文字对照表，并按问题ID关联；v1不为此扩展字段。该复审状态与`status`的证据核实程度不同，已解决的问题不必重复写入新增批注台账。

## `anchor`

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `format` | 枚举，必需 | `pdf` / `docx` / `doc` |
| `page1` | 整数，可选 | 正整数；PDF 指文件中的第几页，从 1 起，而非印刷页码 |
| `quote` | 非空字符串，可选 | 原文精确片段，用于定位而非下指令 |
| `locator` | 非空字符串，可选 | 例如“表2第3行合格率单元格”或段落编号 |
| `bbox` | 四数字数组，可选 | `[x0, y0, x1, y1]`，有限数字；`0 ≤ x0 < x1`、`0 ≤ y0 < y1` |

`quote` 与 `locator` 至少有一项。两项若都提供，都必须为非空字符串。页码和坐标不能单独代替它们。

PDF 坐标约定：左上角为原点，向右/向下为正，单位为 point（1/72 英寸），在处理页面旋转后的视图中定位；写入某个 PDF 库时仍须转换到该库约定。Word 页码随排版变化，优先用稳定文字与表格/段落位置；如使用渲染坐标，应在 `locator` 说明对应渲染版本及坐标单位。校验器不验证页面是否存在、框是否落在页面内、坐标旋转或引文是否匹配。

## `basis` 元素

每个依据对象只接受以下字段：

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `kind` | 枚举，必需 | `standard` / `design` / `report` / `calculation` |
| `citation` | 非空字符串，必需 | 标准全称/编号/条款，或图纸、报告表格、算术依据的可追溯标识 |
| `verified` | 布尔值，必需 | 必须为 JSON `true` 或 `false`，不能用字符串或数字 |
| `reference` | 非空字符串，可选 | 原始来源定位信息；可为公开来源 URL 或本地索引，校验器不访问它 |

对于 `status: confirmed` 的问题，其中每项 `kind: standard` 的依据必须声明 `verified: true`。未核实的规范依据只允许用于 `conditional` 或 `pending` 问题，且正文必须清楚说明条件或待核内容。该规则不表示任意写 `true` 就能证明条文真实、现行或适用；须人工核查标准版本、条款、对象及适用条件。其他依据的真实性同样不能靠结构校验保证。

## 可选 `calculation`

仅接受 `expression`（必需非空字符串）、`inputs`（必需对象，非空名称映射到有限数字）、`result`（必需有限数字）、`unit` 和 `rounding`（可选非空字符串）。`inputs` 可为空，用于纯常量表达式。布尔值不当作数字。

记录清楚代入值、结果单位和修约方法。校验器**不执行或求值** `expression`，也不保证 `result` 正确，更不会用算术复算替代标准适用性判断。

## 运行与退出码

使用 Python 3.9 或以上版本，无第三方依赖。在仓库根目录运行：

```sh
python skills/wuhan-gangwan-report-review/scripts/validate_findings.py examples/findings.synthetic.json
python skills/wuhan-gangwan-report-review/scripts/validate_findings.py examples/findings.synthetic.json --json
```

也可用 `-` 从标准输入读取 UTF-8 JSON。支持 UTF-8 BOM；拒绝重复 JSON 对象键、`NaN`、`Infinity`、`-Infinity` 及溢出产生的无限数。

- `0`：结构通过，不代表工程审核通过。
- `1`：结构不符合本说明。
- `2`：读取、UTF-8 解码、JSON 解析或命令用法失败。

默认结果为 UTF-8 人读输出；`--json` 输出含 `valid`、`errors`、`limitation` 的 JSON。参数用法错误由命令行解析器打印帮助并退出 `2`。
